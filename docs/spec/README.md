## 决策状态

| 标记 | 含义 | 变更规则 |
|---|---|---|
| **锁定** | 已明确确认的产品、叙事或机制事实 | 只有发现内部矛盾、生产验证证明不可行或用户明确改变方向时才修改 |
| **概念基准** | 当前用于制作与比较的视听或形象方向 | 联合复审前不得当成最终资产；复审时保留设计职责，可调整具体形象 |
| **生产验证** | 规则目标已锁定，具体手感、几何或精确数据需在正式内容中继续验证 | 通过代表内容和玩家测试冻结，不重新讨论产品方向 |
| **阶段延期** | 当前不阻塞生产，且已指定负责人和处理门槛 | 到达门槛时处理，不作为无归属待办 |

## 权威顺序与冲突处理

1. 本目录九份核心 Spec 中的明确规则。
2. 视觉、声音基准中该领域更具体且更新的规则。
3. 用户在后续讨论中作出的明确变更决定。
4. 旧候选、工作标题、概念图伪文字、被替换草稿和早期临时数值均不具约束力。

领域内以01至07章定义产品与内容，以08章定义验收门槛，以09章定义当前技术基线。09章不得削弱01至08章已经锁定的产品要求。

同一事项发生冲突时，必须在权威来源中完成修改，并同步检查受影响的需求ID、数据版本、内容清单和回归范围；其他文档只链接权威来源，不复制定义。

## 变更边界

- 产品、叙事、玩法、内容规模和正式表现职责的变更，必须更新对应核心章节及08章验收要求。
- 技术实现不能以方便为由缩减产品要求；触发09章淘汰条件时，应重新评估技术方案。
- 视觉和声音基准不是最终资产，但其设计职责在联合复审前持续有效。
- 历史验证结论只证明可行性；正式工程必须重新建立生产实现与自动化。
- 必须由用户亲自确认的事项及默认授权边界，以[需求与验收](08-requirements-and-acceptance.md#11-人工确认与默认授权边界)为准。
