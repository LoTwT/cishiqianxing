# 此世千形

正式日文标题：**この世界、千のかたち**

一款童话二次元气质的单人方格冒险游戏。玩家将通过路线规划、机关解谜和实地调查，使用有限的功能方块帮助同一个世界安全地变化。

本仓库是《此世千形》的正式生产仓库。历史可行性原型、测试运行和验收证据在独立验证仓库中维护，不复制到这里。

当前仓库正在建立正式工程与内容生产基线，尚无可试玩的正式内容。内容清单 v6、静态地图加载与初始化 v1、五阶段代表路线合同、12 个敌人家族的基础／强化 24 份中央档案，以及规则层与项目级自动化测试均可无头运行。

规则层已提供永久成长、敌人世界、便携背包、接触战评价／原子提交子事务和接触锁定，并接通**世界步提交 v1**：单空间静态水平格网中的合法移动、主动等待与玩家主动接触。`WorldStepTransactionKernel.prepare()` 准备候选，`commit()` 复验完整前态与封印内容后一次性发布聚合状态和事件，统一推进一步。阶段2—6只接受可以证明无效果的输入；需要巡逻、环境、构造、周期或支援执行的场景明确拒绝。战后站位见[04玩法规格](docs/spec/04-gameplay-systems.md#4-世界步与确定性结算)，接口与当前边界见[09技术基线](docs/spec/09-technical-baseline.md)。

静态地图闭环已接通：`.tres` 清单 → 中央校验与防御快照 → `StaticMapInitializer.initialize(map_id, player, inventory, registry)` → `WorldStepState` → 现有世界步事务。初始化从已封印地图生成格网、满耐久基础态敌人与完整空阶段来源，步数从0开始，成长和背包按原值复制。地图来源声明缺失、重复或类型错误时结构化拒绝，不能由加载器的默认空值证明阶段完整。技术验收地图使用第6章上下文和两名真实中央护盾敌人，只验证数据闭环，不代表正式章节地图或最终摆放冻结。

尚未完成完整七阶段玩法、正式关卡／完整路线验收、可玩场景、UI、动画、音频、跨地图交通、撤销历史或存档系统。

## 开发环境

- Godot **4.7.2 Standard**；其他补丁版本、开发版和 .NET/Mono 构建不属于当前生产基线。
- Git 与 [Git LFS](https://git-lfs.com/)；视觉、音频、模型和字体等二进制资源通过 LFS 管理。

首次克隆后执行：

```bash
git lfs install
git lfs pull
git lfs fsck --objects --pointers HEAD
"${GODOT_BIN:-godot}" --headless --path game --script res://tools/verify_environment.gd
```

最后一条命令只检查引擎版本、Standard 构建、Forward+ 配置和 Compatibility 自动回退，不替代下方正式测试入口。若本机 Godot 可执行文件使用其他名称，可通过 `GODOT_BIN` 环境变量指定完整路径。

GitHub 生成的 ZIP 或 tar.gz 源码归档可能只包含 LFS 指针而不包含实际资源。正式制作与复审应使用安装了 Git LFS 的 Git clone，并以上述 `git lfs fsck --objects --pointers HEAD` 结果为准。

GitHub Actions 的 `Baseline / verify` 检查会在 pull request 与 `main` 更新时重新验证 LFS、官方 Godot 4.7.2 Standard 发行包、Forward+／Vulkan 启动和编辑器导入，然后调用与本地相同的正式测试命令。

## 自动化测试

在仓库根目录执行唯一的项目级 headless 测试命令：

```bash
bash game/tools/run_headless_tests.sh
```

- 测试入口自带三道环境守卫：本地 Godot 必须是 `4.7.2.stable.official` 前缀的 Standard 构建；检查正式工程前执行 `--import` 重建导入缓存，新 clone 或拉取后未开过编辑器时不会因类缓存过期报出与源码无关的编译错误；`game/tests` 下每个 `*_tests.gd` 套件都必须加入 `run_tests.gd` 的 `REGISTERED_SUITES` 实际执行清单，运行器在构造套件前核对文件清单与已注册脚本路径，漏注册、重复注册或清单不匹配都会失败。只在 preload、注释或字符串中提到套件不算注册。
- 错误检测的可靠闸门在 bash 层脚本内：已实证 `--check-only` 遇脚本解析错误时退出码仍为 0，且测试体内部的运行期错误可能被计为通过，二者都由脚本对输出流的错误扫描兜底。直接执行 `godot --script res://tests/run_tests.gd` 会绕过正式入口的环境校验、错误扫描和汇总校验，不要这样做。
- `game/src/rules/` 保存不依赖场景树、渲染、物理或输入设备的权威规则类型，包括整数格规则、永久成长的纯运行时领取事务、敌人实例档案解析、敌人世界编目与格位生命周期、便携成品方块背包与临时属性选择候选、确定性接触战候选内核、复验全部相关前态后发布三份新状态的接触战原子提交子事务，接触锁定内核，以及组合格网／玩家／敌人世界／背包的世界步提交 v1。
- `game/src/content/` 保存强类型 `Resource` 内容定义，以及不依赖场景树的 `RefCounted` 注册、校验和快照查询类型；蓝图、配方、全局永久成长、代表路线合同、敌人档案与静态地图共用同一注册职责和内容封印。
- `game/content/` 保存正式 `.tres` 内容；`res://content/content_manifest.tres` 是唯一规范清单入口，并显式引用永久成长、五阶段代表路线合同、敌人档案与静态地图目录，内容发现不扫描目录。
- `game/tests/` 保存显式注册的灰盒夹具、规则测试与唯一测试运行器；目录遍历只核对注册元数据，执行顺序与测试来源仍由显式清单决定。正式入口还会在隔离临时项目中回归实际运行器，验证漏注册、重复注册、失败套件、完整通过及混合套件中的单项零断言；同时复制实际 bash 门面，验证正常通过和断言后运行期报错的退出状态。
- `game/tools/` 保存环境检查与测试命令门面，不承载玩法规则。
- 静态解析失败、Godot 未处理错误、零测试、单项零断言、缺失汇总或任意测试失败都会返回非零退出码；成功日志会列出测试名称、通过数、失败数和断言数。
- 世界步关键机制的可重复消融脚本为 `game/tests/experiments/world_step_transaction_ablation.py`。从任务工作树根目录运行 `python3 game/tests/experiments/world_step_transaction_ablation.py /tmp/world-step-ablation`（使用尚不存在的证据目录）；它先跑本树完整正式入口，再在五份隔离副本中执行原四项机制消融与“一次性候选”反例，复测、恢复和重跑，保留原始日志、精确替换与源码指纹，源工作树不写入消融。
- 地图机制的隔离消融脚本为 `game/tests/experiments/static_map_initialization_ablation.py`，运行 `python3 game/tests/experiments/static_map_initialization_ablation.py /tmp/static-map-ablation`（证据目录须尚不存在）。它验证地图引用／占格诊断、未支持内容拒绝、出生点内容指纹、查询快照隔离，以及原生来源声明校验与声明有效性验封，保留精确变体、源码摘要、正常／移除／恢复的全量日志。引用、占格和未支持内容另受内容封印保护，报告明确区分单项诊断失效与整体拒绝仍然有效。
- 新增测试套件时必须在 `game/tests/run_tests.gd` 中显式注册；敌人世界测试覆盖规范排序、跨空间格位、生命周期矛盾、孤儿格网 actor、内容漂移、派生类型和输入／输出篡改，背包测试覆盖容量层级、堆叠上限、来源、临时属性映射、替换确认、陈旧 revision 和精确前态，接触战事务测试覆盖准备候选不携带权威替换状态、无可调用 PREPARED／COMMITTED 工厂、胜负两种世界变化、临时属性扣除、0伤害阻断、三类陈旧前态、事务之间的内容漂移、接触地址、支援集合、溢出、确定性和篡改失败关闭；世界步接触测试覆盖玩家／敌人主动接触、无接触、选定空间的敌人格网投影、陈旧格位与步数、越界／阻挡、周期失活取消、确定性、防御快照和篡改失败关闭。世界步事务测试另覆盖移动／等待、真实护盾敌档接触胜负、五种临时属性、战后站位、下一步进格、完整前态复验、锁定绑定、步数上限、重复提交、内容漂移、未支持场景与快照隔离；地图套件另从实际 `.tres` 经正式注册与初始化覆盖版本v6、章节平衡、格网／占格、未知内容、缓存隔离、深拷贝和多敌人连续事务；这些技术样例不代表完整七阶段或正式路线验收。在建立隔离测试数据根以前，自动化测试不得直接读写正式 `user://` 数据。
